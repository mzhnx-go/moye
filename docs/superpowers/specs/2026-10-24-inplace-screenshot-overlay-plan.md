# 截图交互改造方案：选区上直接编辑（in-place overlay）

> 日期：2026-10-24
> 状态：**已实施**（全屏遮罩 in-place；旧独立编辑器仅保留给历史测试，生产不再打开）
> 目标：把“框选完 → 复制出一张图 → 另开窗口编辑”改成“框选完仍在原屏幕截图上编辑，选区可继续调整”
> 交接口径：先读第 2、4、6 节；第 13 节是不可破坏的既有约束。

## 1. 用户要的交互（原话拆解）

1. **在选中的时候修改**：框选后仍停留在冻结的屏幕画面上，直接在这块选区上画。
2. **不要选中完自动截图、再在截图上改**：松手不等于完成；不复制、不关闭、不另开编辑器窗口。
3. **选区要有方框 + 一排工具栏**：松手后选区保留，四周有边框和缩放手柄，工具栏跟随选区显示，工具就是现有那套（矩形/箭头/文字/序号/马赛克/模糊/裁剪……）。
4. **选中后还能调整区域**：拖 8 个手柄改大小，拖选区内部移动，尺寸实时显示；调整后标注仍留在屏幕内容上。

## 2. 目标交互（最终形态）

```
工具栏相机 / Alt+A→S / 托盘
        ↓
冻结当前屏幕并压暗（不改变桌面内容）
        ↓
拖出选区（实时显示 W×H）
        ↓
松手：仍在这个全屏遮罩里
  ┌───────────────┐
  │  冻结的屏幕     │  ← 选区外压暗，选区内原亮度
  │  ┌─────────┐  │
  │  │ 选中区域 │  │  ← 白色边框 + 8 个手柄
  │  │  标注…   │  │
  │  └─────────┘  │
  │  [矩形][椭圆]… │  ← 工具栏贴在选区下方（空间不够自动翻到上方）
  └───────────────┘
        ↓
拖手柄调整 / 拖内部移动 / 选工具直接画 / 撤销重做
        ↓
Enter、Ctrl+C、双击选区内、或点“复制” → 复制“选区+标注”合成图，写入历史，关闭遮罩
Ctrl+S → 保存；贴图 → PinWindow；OCR → 识别选区（遮罩保持打开）
Esc / 关闭 → 丢弃本次截图，不复制、不写历史
```

与当前行为的差异：

| 项目 | 现在（`4fef092`） | 改造后 |
|---|---|---|
| 松手 | 立刻裁出图，打开独立 `ScreenshotEditor` 窗口 | 留在全屏遮罩，显示手柄和工具栏 |
| 编辑位置 | 独立小窗口里只看到裁出的图 | 原屏幕冻结画面上直接编辑 |
| 选区调整 | 不能（只能重截） | 8 向缩放 + 内部拖动 + 方向键微调 |
| 复制时机 | 松手立即复制原图 | 用户确认复制时复制“标注后”的选区 |
| 主窗 | 编辑器期间隐藏 | 遮罩期间隐藏，复制/保存/贴图/取消后恢复 |
| 历史 | 编辑器关闭时写入 | 复制/保存/贴图时写入；取消不写 |

## 3. 方案选型

### 方案 A（推荐）：全屏遮罩自己当编辑器，复用场景/图元/工具栏

- 新建 `ScreenshotOverlay(QGraphicsView)`：全屏、无边框、置顶，场景坐标 = 冻结截图的物理像素。
- 场景里：底图（`EditorScene` 现有 base item，z=-1000）+ 标注图元（复用 `items.py`）。
- 压暗层、选区边框、8 个手柄、尺寸文字画在 `QGraphicsView.drawForeground()`：**不属于场景**，导出天然不会带上。
- 选区和手柄用独立的纯几何模型（`selection.py`），便于单测。
- 工具栏复用 `EditorToolbar`，作为 overlay 的子控件，按选区位置摆放。
- 导出：`scene.render(painter, target, selectionRect)`，只渲染底图+标注，尺寸 = 选区物理像素。

优点：改动集中、复用现有 90% 图元/撤销/工具栏代码、导出路径不经过窗口截图。
缺点：事件路由要小心（选区调整 vs 画图 vs 文本编辑 vs 工具栏）。

### 方案 B：把现有 `EditorView` 放进选区内部

- 在选区位置放一个透明 `QGraphicsView`，只显示标注。
- 问题：选区移动/缩放时，标注到底跟屏幕内容走还是跟选区走会打架；跨出选区被裁、放大后要重建场景坐标；文本焦点和手柄事件层级更复杂。
- 结论：不选。

### 方案 C：保留独立编辑器窗口，背后放整屏背景

- 仍然违反“不要另开窗口”，直接排除。

## 5. 坐标系与渲染（最容易写错的地方）

1. **冻结图**：`screen.grabWindow(0)` 得到物理像素；入口统一 `imageops.normalize()`，DPR 归 1。
2. **场景坐标 = 冻结图物理像素**；视图窗口是逻辑像素全屏。视图 transform：`scale = image.width() / view.width()`（≈屏幕 DPR）。
3. **选区模型存场景坐标**（物理像素）；工具栏/手柄绘制用视图逻辑坐标，两处通过 `mapToScene/mapFromScene` 换算。
4. **层级**：
   - 场景：底图 item（z=-1000）+ 标注 item（z≥0，马赛克/模糊 z=-1 保持现状）。
   - `drawForeground`：选区外压暗（alpha 110）、白色边框、8 个手柄、尺寸标签、当前工具预览。导出不含这些。
5. **导出**：`session.render_region(selection_scene_rect)` → 新建 `QImage(rect.size(), ARGB32)`，`scene.render(painter, target, rect)`；结果 DPR=1。
6. **标注裁剪**：编辑时 `painter.setClipRect(selection)` 后再渲染场景（或用视图 clipping），保证画到选区外的部分不可见；导出天然只取选区。
7. **马赛克/模糊底图**：仍从 `scene.base_image()` 取全屏图采样，不要从“已压暗”的画面取。
8. **文本编辑**：`QGraphicsTextItem` 放在场景里；overlay 的 `keyPressEvent` 先看 `scene.focusItem()`，文本编辑中只放行 Esc/Ctrl+Enter，其余交给文本框。
9. **裁剪后底图变小**：场景 `sceneRect` 改为新底图矩形；底图仍画在原屏幕位置（选区左上角）或重置到 (0,0) 均可，但**导出用底图矩形**；选区重置为底图全幅。

## 6. 选区交互规格

### 6.1 手柄

- 8 个：四角 + 四边中点；显示为 8×8 逻辑像素白底深边方块。
- 命中半径 6 逻辑像素；优先级：**手柄 > 工具栏 > 当前绘图工具 > 选区内部移动 > 新建选区**。
- 光标：四角 `SizeFDiagCursor`/`SizeBDiagCursor`，左右 `SizeHorCursor`，上下 `SizeVerCursor`；指针工具在选区内 `SizeAllCursor`；绘图工具十字。

### 6.2 移动/缩放

- 拖手柄：从对边/对角为锚点缩放；最小 8×8 物理像素；钳制在当前屏幕内。
- 拖选区内部（指针工具且未命中图元）：移动整个选区；标注不跟着选区的几何移动（标注锚定屏幕内容），只是显示和导出范围变了。
- 方向键：1px 微调；Shift+方向键 10px；输入框/文本编辑中不响应。
- 拖动过程中实时更新压暗区、尺寸、工具栏位置；松手不再触发任何“完成”动作。
- 工具栏位置：默认选区下方 8px；下方放不下翻到上方；左右钳制在屏幕内；选区太靠下且上方也放不下时，放在选区右侧/左侧（最后兜底贴在屏幕底部）。

### 6.3 指针工具的语义

- 单击图元：选中图元（可拖动、Delete 删除、改色/改粗细）。
- 拖动空白处但仍在选区内：移动选区。
- 拖动选区外：重新框选（替换当前选区；若已有标注，标注保留，按新选区裁剪显示）。
- 双击空白：复制（PixPin 手感）；双击文字：进入编辑。

## 7. 工具行为

| 工具 | 行为 |
|---|---|
| 指针 | 选中/移动图元；拖动选区内部移动选区 |
| 矩形/椭圆/箭头 | 在选区内拖拽绘制；点太小丢弃；可撤销 |
| 画笔/马克笔 | 自由手绘；马克笔半透明；选区内裁剪显示 |
| 文字 | 选区内点击输入；Ctrl+Enter 结束；Esc 结束编辑但**不关闭遮罩**；空文本自动移除 |
| 序号 | 选区内点击生成 1、2、3…；撤销不回退计数（PixPin 同款） |
| 马赛克/模糊 | 选区内的二级区域；从冻结底图采样；效果图元 z=-1 |
| 裁剪 | **应用当前选区为新底图**：底图改为选区内容，标注平移，选区重置为新底图全幅；可撤销。保留“裁剪”按钮，避免功能回退 |
| 撤销/重做 | 覆盖：加图元/删图元/裁剪/马赛克/模糊；不关闭遮罩 |
| 颜色/粗细 | 作用于新图元；选中图元时即时改色/改粗细（现有实现保留） |

## 8. 动作与生命周期

| 动作 | 行为 |
|---|---|
| 复制（Enter / Ctrl+C / 工具栏 / 双击空白） | 渲染“选区+标注” → 剪贴板 → 历史 +1 → 关闭遮罩、恢复主窗；**不自动插入笔记** |

| 取消（Esc / 关闭） | 关闭遮罩、恢复主窗；不复制、不写历史 |
| 调整选区/画图/撤销 | 不写历史、不关闭 |

- 历史条目在图 **确认动作**（复制/保存/贴图）时写入；`source` 仍为 region/window/fullscreen/last。
- 主窗在 overlay 打开期间保持隐藏；overlay 关闭后恢复；批注层模式按原状恢复（沿用 `ScreenshotController._hide_annotate/_restore_annotate`）。
- `Alt+A→S` 两步热键不变。

## 10. 实施阶段（每阶段可单独提交/回滚）

### Phase A：选区底座（先解决“不能调整”）

验收：每种工具画完可撤销、可复制；文字编辑中 B/Q/数字/Enter 不误触。

### Phase C：模式/OCR/清理

1. 全屏/窗口/上一区域改传初始选区；窗口模式映射与 DPI。
2. OCR 接入选区导出；Lite 仍隐藏。
3. 移除独立 `ScreenshotEditor` 窗口与 `annotate/capture.py` 旧遮罩；`annotate` 入口统一委托截图控制器。
4. 迁移旧测试，补齐 overlay/controller/app 测试。
5. 真机副屏 150% + 主屏回归；更新 `docs/REPORT.md`。

## 12. 风险与待定

- **事件优先级**是最容易出错处：手柄、工具栏、图元、选区、新框选必须固定顺序并写测试。
- **文本焦点**：overlay 是 QGraphicsView，文本编辑时快捷键必须全部让路；Enter 默认行为要区分“复制”和“换行”。
- **选区移动时标注是否跟着走**：本方案定为“标注锚定屏幕内容，选区只改导出范围”。如果用户期望“移动选区带着标注一起走”，改起来会牵扯场景平移，需先确认（建议先按本方案）。
- **裁剪语义**：本方案定为“把当前选区变成新底图，继续编辑”。如果觉得多余，可降级为“裁剪并复制后关闭”，实现更简单。
- **全屏场景重绘性能**：底图用缓存 `QPixmap`，避免每次 paint 重新 fromImage；选区改变只更新 viewport。
- **跨屏选区**不支持；窗口跨屏时只能截当前屏幕部分。
- **OCR 仍在 UI 线程**（现状），大图可能卡 1–3 秒；不在本次扩大范围。
- 全量测试单跑约 9.5 分钟，**不要同时跑两个全量**（会假死）；按文件分组更稳。

## 13. 交接约束（不可破坏）

- `Alt+A→S` 仍是两步全局热键（Windows 不能一次注册三键）。
- 截图**只进剪贴板，不自动插入笔记**；现在也不在松手时自动复制，只在用户确认复制时复制。
- 主窗/批注层：截图期间隐藏，结束后恢复原模式。
- 历史目录 `data/screenshots`（Lite 自动落到 `data-lite/`）；默认 100 条/30 天。
- OCR 只 Standard：`ocr_available()` 已有产品线判断，Lite 不显示按钮、不 import 引擎。
- 零新增外部依赖；不打包（用户明说才打包）。
- 现有 `4fef092` 是可用回退点；本次改造不要顺手改 Word/转换/笔记链路。
