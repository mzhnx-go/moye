# SketchPad v2 功能规划（PDF 批注）

日期：2026-10-21
状态：**已确认**（2026-10-21，用户对 §10 四项均选推荐项）
参考对象：Xournal++（用户指定），以及 v1 已交付的草稿板（`docs/superpowers/specs/2026-10-20-sketchpad-design.md`）

## 1. 定位

v1 是"随身草稿板"：无限画布、笔迹、清屏、草稿窗。v2 加一个**文档模式**：打开 PDF，逐页在上面涂写，同时保留草稿窗做计算。

v1 与 v2 共存，不做功能替换：
- **草稿模式**：现在的无限画布（内存文档，不落盘）。
- **文档模式**：打开 PDF → 逐页批注 → 保存批注 / 导出 PDF。

两种模式共用同一套笔迹引擎（`app/canvas.py` 的 SketchView + `app/strokes.py` 的模型），渲染/输入不重写。

## 2. 用户场景（基于现有习惯）

用户在 Xournal++ 里打开四海讲义 PDF 做题。v2 后的流程：

1. 打开讲义 PDF（菜单 / 拖进窗口）
2. `Alt+Q` 弹出草稿窗算题（沿用 v1，不改）
3. 在 PDF 页面上直接用笔批注（划线、圈、写答案）
4. 翻页继续；`Ctrl+S` 保存批注；需要交付时导出新 PDF

## 3. 功能范围

### 3.1 做

| 编号 | 功能 | 口径 |
|---|---|---|
| V1 | 打开 PDF | 菜单 / 拖拽；支持多页、横竖混合、旋转页；加密 PDF 明确报错不崩 |
| V2 | 页面渲染 | 按当前缩放渲染页面位图，缩放档位缓存；页面之间留 8px 间隙，连续纵向排列 |
| V3 | 逐页批注 | 复用 v1 的画笔 / 橡皮 / 颜色 / 1–48 粗细；笔迹存**页面坐标（PDF 点）**，缩放不回算 |
| V4 | 翻页导航 | `PgUp`/`PgDn`、滚轮滚动、页码框输入 + 回车跳转、`Ctrl+G` 跳页 |
| V5 | 保存批注 | 同目录 sidecar：`<文件名>.sketch.json`（可编辑、非破坏）；`Ctrl+S` 原子写 |
| V6 | 导出 PDF | 把笔迹"烧"进新 PDF（矢量路径），另存不覆盖原文件；导出前提示页数/笔迹数 |
| V7 | 草稿窗 | 完全沿用 v1（全局热键、恒置顶、内存文档、独立撤销）；文档模式下同样可呼出 |
| V8 | 菜单栏 | 仿 Xournal++：文件 / 编辑 / 视图 / 导航 / 页面 / 工具 / 帮助（见 §6） |
| V9 | 撤销/重做 | 沿用 v1 的 History；按页记账，跨页撤销时自动跳到对应页 |
| V10 | 打开最近文件 | 菜单"文件 → 最近打开"，最多 10 条，存 `settings.json` |

### 3.2 不做（写死，防止蔓延）

- 手写识别 / 文字层 / 文本编辑
- 图层（Xournal++ 有，v2 不做）
- PDF 表单填写、书签、目录跳转、注释（annotation）编辑
- 高亮笔、荧光笔、图片插入、图形工具（矩形/圆/直线暂不做）
- 插件系统（菜单栏"插件"不出现，不留空项）
- 协作、云同步、多标签页
- 编辑原 PDF 文件本身（只导出副本）

## 4. 技术方案

### 4.1 PDF 渲染与写回（决策点 A）

| 方案 | 依赖 | 许可 | 优点 | 代价 |
|---|---|---|---|---|
| A1（推荐） | PyMuPDF (`pymupdf`) | **AGPL-3.0**（商用需授权） | 渲染 + 写回一套库，工作量最小；导出矢量笔迹有现成 API | 若以后分发，AGPL 传染性需要注意；个人本地使用无影响 |
| A2 | `pypdfium2`（渲染，Apache/BSD）+ `pypdf`（写回，BSD） | 宽松 | 可分发的商业友好组合 | 两个库、两套坐标系；写回要自己拼 content stream，工作量约 +2 天 |

建议：**A1**。本项目是本地个人工具，不分发；文档里注明"若将来分发需换 A2 或购买授权"。

### 4.2 数据模型（页面坐标）

```python
Page:  width_pt: float, height_pt: float, rotation: int,
       strokes: list[Stroke],          # 复用的 v1 Stroke，点是页面坐标（PDF 点）
       source_index: int | None        # None = 空白页（v2 不提供插入，留字段）

PdfDocument:
    path: Path, page_count: int,
    pages: list[Page],
    sidecar: Path                       # <pdf>.sketch.json
```

- 笔迹点一律存 **PDF 点**（1pt = 1/72 英寸），与渲染 DPI 解耦。
- 缩放只改视图变换，不改笔迹数据（与 v1 的世界坐标同一原则）。
- 页间滚动 = 变换平移；不存在 v1 那种"无限画布"。

### 4.3 渲染策略

- 每页一个 `QGraphicsItemGroup`：页面底图（QPixmap，按缩放档渲染并缓存）+ 该页笔迹的 path 项。
- 渲染档位：按缩放取整到 {25, 50, 75, 100, 150, 200, 300, 400}%，换档才重渲；同一档复用位图。
- 视口外的页不渲染底图（只保留占位矩形），滚动到位再渲。
- 笔迹线宽按页面点存；屏幕像素 = 点 × 缩放。

### 4.4 存储与导出

- sidecar JSON：`{"version":1, "pdf": "文件名", "pages":[{"strokes":[...]}]}`；只存笔迹，不存 PDF 内容。
- 原子写：`.tmp` → `os.replace`（沿用 v1 storage 的做法；v1 的 storage 已删，v2 重建一个 `app/pdf_store.py`）。
- 打开 PDF 时自动配对 sidecar；找不到就是空白批注。
- 导出：新文件名默认 `<原名>-批注.pdf`，不覆盖原文件。

### 4.5 与 v1 的代码关系

| v1 模块 | v2 用法 |
|---|---|
| `app/strokes.py` | 直接复用（点、颜色、线宽、抽稀） |
| `app/history.py`、`app/commands.py` | 复用；`AddStroke` 需要支持"哪一页"，命令里带 page 引用 |
| `app/canvas.py` | 抽出笔迹绘制/橡皮逻辑，供 `PdfView` 复用；无限画布行为不变 |
| `app/scratch.py` | 不动（草稿窗照样工作） |
| `app/toolbox.py` | 复用，文档模式下增加页码/翻页按钮（或交给菜单栏/快捷键） |
| 菜单栏 | 新增 `app/menubar.py`，两种模式共用；模式切换时启用/禁用条目 |

## 7. 性能线（必须达标，不再重蹈 v1）

v1 实测：1000 条 × 200 点，100% 缩放一帧 30 s（离屏软件光栅），未达标。v2 文档模式必然面对"一页几百条笔迹"，所以 v2 自带优化，不等事后补：

- **页面级裁剪**：只渲染视口内的页；页面底图为位图。
- **瓦片合并**：同一页内每 200 条已固化笔迹合并成一个 `QGraphicsPathItem`；抬笔时增量合并，不整页重建。
- 验收线：**一页 500 条 × 平均 100 点**，100% 缩放平移/缩放持续 ≥ 50 fps（单帧 ≤ 20ms），在真实窗口测，不用离屏数字。

### 7.1 实施修正（2026-10-20，实测结论，以本节为准）

"瓦片合并"经实测**证伪并弃用**：500 条独立矢量项 123.8ms/帧，按 (颜色,粗细)
合并成 32 个巨路径项后 **1658.4ms/帧（慢 13 倍）**——巨路径失去逐项裁剪，
光栅化整路径重算。改用**笔迹位图缓存**（详见 `docs/verification/perf-pdf-2026-10-20.md`）：

- 每页一张透明位图缓存已固化笔迹（按当前缩放烘一次，之后每帧只 blit）；
- 尾部 `STROKE_TAIL=16` 条最新笔迹保留矢量项（落笔预览/橡皮实时反馈/撤销粒度）；
- 抬笔时超长部分**增量**画进缓存（保留原 §7"增量合并不整页重建"的意图）；
- 擦已烘笔迹/清页/撤销重做 → 按剩余笔迹整体重渲缓存。

实测（真实窗口，500 条 × 100 点）：100% 静态/平移 **6.5ms**、200% 静态 **8.6ms**，
验收线达标。实测工具 `tools/perf_pdf.py`。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| PDF 旋转页 / 非整数尺寸 | 统一按渲染后的页面矩形做坐标；旋转在渲染层处理，笔迹仍存未旋转页面坐标 |
| 加密 / 损坏 PDF | 打不开时明确提示，不进入文档模式，不崩 |
| 大页面（A0）内存 | 底图按视口分块渲染 + 限制缓存页数（最多 3 页） |
| 导出笔迹错位 | 导出前用同一坐标系重算；验收含"导出后与原预览逐点对照" |
| AGPL 依赖 | 本地使用不分发；若要分发，切 A2 或购授权（决策点 A） |
| v1 的草稿不保存 vs v2 要保存 | 两套语义并存：草稿窗仍不保存；PDF 批注必须保存，且保存失败要显式提示 |

## 10. 已确认的决策（2026-10-21）

| 决策 | 结论 | 来源 |
|---|---|---|
| PDF 库 | **A1 PyMuPDF**（AGPL；本地个人使用，不分发；将来分发再切 A2） | 用户 2026-10-21 选择 |
| 保存方式 | **sidecar + 导出**：`<PDF名>.sketch.json` 可编辑，交付时导出新 PDF | 同上 |
| 阅读方式 | **连续纵向滚动**，页码随滚动更新 | 同上 |
| 导出 | **只导出副本** `<原名>-批注.pdf`，绝不修改原文件 | 同上 |

由这四项派生、直接写进实施约束：
- 不实现"直接写回原 PDF"的路径，代码里也不留开关。
- `Ctrl+S` 只写 sidecar；导出需显式触发（菜单或 `Ctrl+Shift+E`）。
- 连续滚动模式下，页码框显示"当前视口中心所在的页"。
- PyMuPDF 版本钉在 `requirements.txt`，并在 README/交接文档里注明 AGPL 与"不分发"的前提。

## 11. 验收清单（v2）

1. 打开一份 20 页讲义 PDF，翻到第 10 页，页码显示 10/20。
2. 在第 10 页画 5 笔，`Ctrl+Z` 撤 1 笔，其余 4 笔位置与颜色不变。
3. 缩放 200% 再画一笔，笔迹落点仍在笔尖下；缩回 100% 不变形。
4. 翻到第 3 页再翻回来，第 10 页的 5 笔还在。
5. `Ctrl+S` 后重启，批注自动恢复（sidecar）。
6. 导出 PDF：新文件存在、原 PDF 未被改动、笔迹落在页面对应位置。
7. 文档模式下按 `Alt+Q` 弹出草稿窗，画几笔，收起再打开内容还在。
8. 一页放 500 条笔迹，平移/缩放不卡（§7 的实测数字）。
